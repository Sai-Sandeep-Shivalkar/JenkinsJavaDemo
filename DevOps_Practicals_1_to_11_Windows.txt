PRACTICAL 1 - INITIALIZE A GIT REPOSITORY AND PERFORM BASIC OPERATIONS
============================================================
AIM:
Create a StudentManagement project, initialize Git, stage and commit files, modify a file, view commit history, compare changes, and finish with a clean working tree.

STEP 1 - CREATE PROJECT USING FILE EXPLORER
1. Create a folder named StudentManagement.
2. Copy the instructor-provided README.md into this folder. Do not create a replacement if one was supplied.

Expected structure:

STEP 2 - OPEN COMMAND PROMPT IN THE PROJECT FOLDER

STEP 3 - CONFIGURE GIT IDENTITY LOCALLY
Use your own name and email:
    git config user.name "Your Name"
    git config user.email "your-email@example.com"

Check:
    git config user.name
    git config user.email

STEP 4 - INITIALIZE GIT AND CHECK STATUS
    git init
    git status

STEP 5 - STAGE THE FILES
    git add .
    git status
    git diff --staged

STEP 6 - CREATE FIRST COMMIT
    git commit -m "Initial commit for StudentManagement"
    git log --oneline

STEP 7 - MODIFY README.MD USING NOTEPAD OR VS CODE
1. Open README.md.
2. Keep the original content and add a Features heading and one or two feature lines at the bottom.
3. Save the file.

Example lines (only if suitable for the instructor's README):
    Features:
    - Add student records
    - View student details
    - Manage student information

STEP 8 - VIEW UNSTAGED CHANGES
    git status
    git diff

STEP 9 - STAGE AND COMMIT THE MODIFICATION
    git add README.md
    git status
    git diff --staged
    git commit -m "Add StudentManagement features"

STEP 10 - VIEW HISTORY AND COMPARE COMMITS
    git log --oneline
    git show --stat --oneline HEAD
    git diff HEAD~1 HEAD

STEP 11 - CHECK FINAL STATUS
    git status
Expected: nothing to commit, working tree clean.

IMPORTANT COMMANDS:
    git init                 Initialize repository
    git status               Check status
    git add .                Stage all files
    git commit -m "message" Create a commit
    git diff                 Show unstaged changes
    git diff --staged        Show staged changes
    git log --oneline        Show commit history
    git diff HEAD~1 HEAD     Compare previous and latest commits

PRACTICAL 5 - GIT MERGE CONFLICT RESOLUTION
============================================================
AIM:
Create two branches, edit the same line differently, generate a merge conflict, resolve it, and complete the merge.

STEP 1 - CREATE FOLDER AND FILE USING GUI
Create folder GitMergeConflict. Inside it create book.txt containing:
    Book Status: Available

STEP 2 - OPEN CMD IN THE FOLDER AND SET LOCAL IDENTITY
    git config user.name "Your Name"
    git config user.email "your-email@example.com"

STEP 3 - INITIALIZE AND COMMIT
    git init
    git add .
    git commit -m "Initial book status"
    git branch -M main

STEP 4 - CREATE FEATURE BRANCH
    git switch -c feature-status

Open book.txt and change the line to:
    Book Status: Reserved
Save, then run:
    git add book.txt
    git commit -m "Set book status to Reserved"

STEP 5 - SWITCH TO MAIN AND MAKE A DIFFERENT CHANGE
    git switch main

Open book.txt and change the same line to:
    Book Status: Issued
Save, then run:
    git add book.txt
    git commit -m "Set book status to Issued"

STEP 6 - CREATE THE CONFLICT
    git merge feature-status
Git should report a conflict in book.txt because the same line was changed differently on both branches.

STEP 7 - RESOLVE USING NOTEPAD OR VS CODE
Open book.txt. It may show conflict markers like:
    <<<<<<< HEAD
    Book Status: Issued
    =======
    Book Status: Reserved
    >>>>>>> feature-status

Delete all marker lines and choose the final content, for example:
    Book Status: Issued (reservation request reviewed)

Save the file. Do not leave any conflict markers in the final file.

STEP 8 - COMPLETE THE MERGE
    git status
    git add book.txt
    git status
    git commit -m "Resolve book status merge conflict"

STEP 9 - VERIFY
    type book.txt
    git log --oneline --graph --all
    git branch
    git status
Expected: nothing to commit, working tree clean.

IMPORTANT:
- A branch is a separate line of development.
- A merge conflict occurs when Git cannot automatically combine overlapping changes.
- To cancel an unfinished merge before resolving it, use git merge --abort.

@echo off

echo ====================================
echo       JENKINS FREESTYLE BUILD

REM TODO 1: Display a welcome message with the project name
echo Welcome to Jenkins Freestyle Build

REM TODO 2: Display the current date and time

cd

echo Project Name: Jenkins Freestyle Build
echo Build Date: %DATE% %TIME%
echo Build Status: SUCCESS

REM TODO 7: Display contents of build-report.txt
type output\build-report.txt

echo ====================================
echo       BUILD COMPLETED
echo ====================================

1. Click Save.
2. Click Build Now.
3. Click the new build number in Build History.
4. Click Console Output.

STEP 6 - VERIFY OUTPUT FILE
Open the job Workspace. Check that output\build-report.txt exists and contains Project Name, Build Date, and Build Status.

WINDOWS COMMANDS TO REMEMBER:
    echo %DATE% %TIME%   Date and time
    echo %USERNAME%      Logged-in user
    ver                  Windows version
    cd                   Current directory
    if not exist ...     Create folder if missing
    type file.txt        Display a text file in Windows CMD

MAC JENKINS NOTE:
Your home Jenkins runs on macOS. For that Jenkins instance, choose Execute shell and use this equivalent script instead:

#!/bin/bash
echo "===================================="
echo "       JENKINS FREESTYLE BUILD"
echo "===================================="
echo "Welcome to Jenkins Freestyle Build"
echo "Build Started Successfully"
echo "Current Date and Time: $(date)"
echo "Logged-in User: $(whoami)"
echo "Operating System: $(uname -a)"
echo "Current Working Directory: $(pwd)"
mkdir -p output
cat > output/build-report.txt <<EOF
Project Name: Jenkins Freestyle Build
Build Date: $(date)
Build Status: SUCCESS
EOF
echo "===== BUILD REPORT ====="
cat output/build-report.txt
echo "===================================="
echo "       BUILD COMPLETED"
echo "===================================="

Do not paste Windows batch syntax such as @echo off into a Mac Execute shell step. Do not use cat in Windows CMD; use type.

public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public int subtract(int a, int b) {
        return a - b;
    }

    public int multiply(int a, int b) {
        return a * b;
    }

    public double divide(double a, double b) {
        if (b == 0) {
            throw new IllegalArgumentException("Division by zero is not allowed.");
        }
        return a / b;
    }
}

STEP 3 - CalculatorTest.java
Save at src\test\java\CalculatorTest.java:

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {
    private Calculator calculator;

    @BeforeEach
    void setup() {
        calculator = new Calculator();
    }

    @Test
    void testAddition() {
        assertEquals(8, calculator.add(5, 3));
    }

    @Test
    void testSubtraction() {
        assertEquals(2, calculator.subtract(5, 3));
    }

    @Test
    void testMultiplication() {
        assertEquals(15, calculator.multiply(5, 3));
    }

    @Test
    void testDivision() {
        assertEquals(2.5, calculator.divide(5, 2), 0.001);
    }

    @Test
    void testDivisionByZero() {
        assertThrows(IllegalArgumentException.class,
                () -> calculator.divide(5, 0));
    }

    @Test
    void testNegativeAddition() {
        assertEquals(-2, calculator.add(-5, 3));
    }

    @Test
    void testMultiplicationByZero() {
        assertEquals(0, calculator.multiply(10, 0));
    }
}

        // TODO 1: Create ChromeOptions and configure the browser if required.
        ChromeOptions options = new ChromeOptions();

        // TODO 2: Initialize the ChromeDriver.
        driver = new ChromeDriver(options);

        // TODO 3: Maximize the browser window.
        driver.manage().window().maximize();

        Path page = Paths.get("webapp", "index.html").toAbsolutePath();
        driver.get(page.toUri().toString());
    }

    @Test
    public void validLoginShouldShowSuccessMessage() throws Exception {
        // TODO 5: Locate username field and enter valid credentials.
        driver.findElement(By.id("username")).sendKeys("student");

        // TODO 6: Locate password field and enter valid credentials.
        driver.findElement(By.id("password")).sendKeys("Selenium@123");

        // TODO 7: Click the login button.
        driver.findElement(By.id("loginBtn")).click();

        // TODO 8: Retrieve the response message.
        String message = driver.findElement(By.id("message")).getText();

        // TODO 9: Assert that the success message is displayed.
        assertTrue(message.contains("Login successful!"));

        // TODO 10: Capture screenshot.
        saveScreenshot("successful-login.png");
    }

    @Test
    public void invalidLoginShouldShowErrorMessage() throws Exception {
        // TODO 11: Enter invalid username/password and click login.
        driver.findElement(By.id("username")).sendKeys("wrong");
        driver.findElement(By.id("password")).sendKeys("wrong");
        driver.findElement(By.id("loginBtn")).click();

        // TODO 12: Retrieve response message and assert error message.
        String message = driver.findElement(By.id("message")).getText();
        assertEquals("Invalid username or password!", message);

        // TODO 13: Capture screenshot.
        saveScreenshot("invalid-login.png");
    }

    private void saveScreenshot(String fileName) throws Exception {
        // TODO 14: Capture current browser screen and save in screenshots/.
        File folder = new File("screenshots");
        folder.mkdirs();
        File source = ((TakesScreenshot) driver).getScreenshotAs(OutputType.FILE);
        File destination = new File("screenshots/" + fileName);
        FileHandler.copy(source, destination);
    }

    @AfterEach
    public void tearDown() {
        // TODO 15: Close browser safely if initialized.
        if (driver != null) {
            driver.quit();
        }
    }
}

    git config user.name "Your Name"

    git config --local --unset user.email

This removes the local commit identity, but does not automatically remove saved GitHub/GitLab login credentials. Also sign out of the browser and remove saved credentials from Windows Credential Manager if you used them.
